# AGENTS.md

## Project Overview

This repository is a React Native boilerplate using Expo prebuild, TypeScript, Zustand, TanStack React Query, NativeWind, and Expo Updates.

The UI layer is built on local primitives in `src/presentation/components/ui/` styled with
NativeWind. Gluestack UI was removed; see `Styling System` below.

The project is not a pure managed Expo app. Native iOS and Android projects are generated by Expo prebuild, then extended by config plugins to support multiple environments.

Core assumptions:

- Package manager: `pnpm`
- Runtime: Node.js `>=22.11.0`
- Expo SDK: `56`
- React Native: `0.85.3`
- Environment source of truth: `app.config.ts`
- Native environment generation: `plugins/with-environment-support.cjs`
- Runtime app config access: `src/shared/config/appConfig.ts`
- OTA update docs: `docs/EXPO_UPDATES.md`

## Expo Config Rules

`app.config.ts` is the source of truth for:

- app variant metadata
- iOS bundle identifiers
- Android application IDs
- display names
- native version fields
- Expo Updates metadata
- runtime `extra` values
- branding asset paths

Do not hardcode environment behavior in application code if it belongs in `app.config.ts`.

JS runtime code should read app config through:

```ts
import { appConfig } from '@/shared/config/appConfig';
```

Avoid reading `process.env` directly in app runtime code unless there is a deliberate reason.

Per-variant native identifiers are centralized in `scripts/lib/variant-config.cjs`, shared
by `app.config.ts`, `scripts/run-native.cjs`, and `scripts/sync-native-env.cjs`. Bundle
identifiers, package names, schemes, Gradle variants, and update channels are derived
there rather than restated per file — `run-native.cjs` passes `--app-id` to the launch
step, so a package name that drifts from `app.config.ts` produces a build that installs
fine and then fails to start. Change identifiers in `variant-config.cjs`, never in a
consumer.

## Native Generation Model

`pnpm prebuild:clean` runs:

```bash
expo prebuild --clean
```

This deletes and regenerates `ios/` and `android/`.

The project must remain reproducible after `pnpm prebuild:clean`.

The config plugin at `plugins/with-environment-support.cjs` regenerates native environment support:

- Android product flavors: `development`, `staging`, `production`
- Android default flavor: `development`
- Android variants: `developmentDebug`, `stagingDebug`, `productionDebug`
- iOS default development scheme: `NewReactNativeZustandRNQ`
- iOS explicit schemes: `Staging`, `Production`
- iOS explicit configurations: `Staging.Debug`, `Staging.Release`, `Production.Debug`, `Production.Release`
- Podfile project configuration mappings
- iOS build settings for `APP_VARIANT`, `ENVFILE`, bundle id, display name, and version
- Android Gradle task environment injection for `expo-constants`

## Native Editing Rules

Treat `ios/` and `android/` as generated output unless the user explicitly chooses a bare-native workflow.

Do not place important custom native code only inside generated files if it must survive `prebuild --clean`.

Use these approaches instead:

- Config plugin for native configuration changes: plist, manifest, Gradle, Podfile, schemes, build settings, permissions.
- Local Expo module for Swift/Kotlin native bridge code.
- `assets/branding/` for app icon and splash source assets.

If a required change is made directly under `ios/` or `android/`, also add the corresponding config plugin or documented regeneration step, otherwise the change is fragile.

## Native Bridge Guidance

For custom native APIs exposed to React Native, prefer a local Expo module outside generated native folders:

```txt
modules/
  my-native-feature/
    expo-module.config.json
    ios/
    android/
    src/
```

The app can import the module through a TypeScript wrapper. Expo autolinking should reconnect it during prebuild/build.

Use config plugins for wiring and local Expo modules for real Swift/Kotlin implementation.

## Expo Updates Rules

Read `docs/EXPO_UPDATES.md` before changing OTA behavior.

Important constraints:

- OTA updates only apply to compatible native binaries.
- `runtimeVersion` is tied to `VERSION_NAME`.
- `EXPO_UPDATE_CHANNEL` should usually match `APP_VARIANT`.
- OTA is disabled in `__DEV__`.
- Native dependency or config changes require a new native build.

Use:

```bash
pnpm update:push
pnpm update:list
pnpm update:check
pnpm update:test
```

## Source Structure

Primary source folders:

- `src/app/`: providers and app-level state setup
- `src/core/`: cross-cutting error classification
- `src/data/`: API, HTTP client, persistence, infrastructure services
- `src/presentation/`: screens, navigation, hooks, UI
- `src/shared/`: config, constants, models, style, types, utilities

Keep layer boundaries clear:

- UI should not own API client details.
- Data services should not own screen behavior.
- Shared code should stay generic and reusable.
- Environment access should go through shared config.

### Import Aliases

Use the `@/` form for all new code:

```ts
import { appConfig } from '@/shared/config/appConfig';
import store from '@/app/store';
```

`tsconfig.json` also declares short aliases (`@app/*`, `@data/*`, `@shared/*`,
`@presentation/*`) and a few existing files still use them. Treat those as legacy.
Do not introduce new ones, and prefer converting them opportunistically when already
editing a file.

## Runtime Architecture

Provider order, entry `index.js` → `src/Root.tsx` → `src/App.tsx`:

```txt
QueryProvider              (src/Root.tsx)
  ErrorBoundary            (src/presentation/components/ErrorBoundary.tsx)
    GestureHandlerRootView
      SafeAreaProvider
        ThemeProvider      (src/presentation/components/ui/theme-provider)
          AppStack         (src/presentation/navigator/AppStack.tsx)
          ModalUpdate
```

`QueryClientProvider` deliberately lives in `Root.tsx`, outside `App.tsx`, so the
query client outlives the rest of the tree.

Reactotron is loaded through an inline `require` inside `if (__DEV__)`, not a static
import, because Metro does no cross-module dead-code elimination. Keep it that way when
touching dev-only wiring.

### State

One Zustand store today: `useCounterStore` (`src/app/store/counterStore.ts`).

Stores are created through `createStore(name, creator)` in
`src/app/store/storeFactory.ts`, which applies the Reactotron enhancer in dev only and
registers a reset function so `resetAllStores()` can return every store to its initial
state.

There is no `persist`, `immer`, or `devtools` middleware, and no slice pattern.

Stores are consumed through the default namespace export:

```ts
import store from '@/app/store';

const count = store.useCounterStore(state => state.count);
```

Use `useShallow` for multi-field selections.

### Data Layer

`HttpClient` (`src/data/services/httpClient/httpClient.ts`) is a singleton composed of
four collaborators: `ErrorHandler`, `TokenService`, `RequestInterceptor`, `RateLimiter`.

- Base URL comes from `appConfig.apiUrl` and is validated at construction by
  `assertValidApiUrl` (`src/shared/config/api-url.ts`), which **throws at startup** on a
  missing scheme, empty authority, or plain `http://` in staging/production.
- Requests are pre-validated for endpoint shape, path traversal, and method, then rate
  limited (`networkConfig` in `src/shared/config/appConfig.ts`).
- The access token is set as an axios instance default header by
  `HttpClient.setAccessToken`, not attached per request.
- `HttpResponse<T>` has no `ok` flag and no `error` field. Failures throw. Do not write
  branches that test for a success flag on a resolved response.

Auth refresh lives in `src/data/services/httpClient/services/tokenService.ts`:

- Single-flight refresh with an identity check before clearing the in-flight promise.
- A `sessionEpoch` counter checked on both sides of the keystore write, so a refresh that
  resolves after logout cannot resurrect a session.
- Only 401/403 or a missing credential clears the token; transport failures keep it up to
  `MAX_CONSECUTIVE_FAILURES`.
- Proactive refresh is scheduled shortly before expiry.

The refresh request itself goes out on a separate, interceptor-free axios instance
(`services/refresh-client.ts`) with its own timeout and abort controller, so it can never
recurse through the 401 handler.

The response interceptor (`services/requestInterceptor.ts`) sets `config._retry` **before**
dispatching the refresh, which is what stops 401 replay from recursing.

### Query Conventions

`src/data/queries/` holds the TanStack Query hooks, re-exported through a default
namespace object mirroring the store convention.

- Query client config is in `src/app/providers/queryClient.ts`: 5min `staleTime`,
  10min `gcTime`, `retry: 2`, no window-focus refetch, no persistence.
- Always thread the `signal` from `queryFn` into the API call so unmount aborts propagate.
- Presentation code consumes queries through a hook in `src/presentation/hooks/`, not
  directly in screens.

### Error Model

`src/shared/errors/AppError.ts` defines the hierarchy. Every error carries a `code`,
`severity`, timestamped `context`, and a `recoveryStrategy`
(`shouldRetry` / `shouldLogout` / `shouldShowAlert` / retry count and delay). Subclasses
set `Object.setPrototypeOf` so `instanceof` survives transpilation — keep that when adding
one.

`src/core/error/ErrorHandler.ts` classifies anything thrown into an `AppError`. Two
ordering constraints are load-bearing and easy to break:

- Cancellation is checked before the "no response" network branch, so React Query's
  unmount aborts are not reported as connectivity failures.
- `token expired` is checked before the generic `auth` match.

Errors reach the UI by exactly two paths: a rejected query surfacing through the hook's
`error` field, or a render-time throw caught by `ErrorBoundary`.

### Presentation

- Screens live at `src/presentation/screens/<name>/index.tsx` with co-located
  `components/`, `hooks/`, `constants/`, and `__tests__/`. `signup` is the fully worked
  example.
- Navigation is React Navigation v7 with a stack navigator. Route names come from the
  `RouteName` const in `src/shared/constants/routeName.ts`.
- `RootNavigator` (`src/data/services/navigation/rootNavigator.ts`) provides imperative
  navigation outside components, guarded by `isReady()`.
- Forms use react-hook-form with `zodResolver` and schemas from
  `@/shared/validation/schemas`.

### Styling System

Gluestack UI has been removed. The current stack is NativeWind v4 plus a small local
variant engine in `src/shared/style/`:

- `cn()` (`class-names.ts`) merges classes through `twMerge`; last wins, so caller
  classes go last.
- `tv()` (`tailwind-variants.ts`) is a local reimplementation. **Variant defaults are
  deliberately unsupported** — components default in their own prop destructuring
  (`size = 'md'`) instead.

Each UI primitive under `src/presentation/components/ui/<name>/` follows one shape:

- `styles.tsx` exporting a `tv({ base, variants, compoundVariants })` table.
- `index.tsx` with a `forwardRef` component whose props are the RN component props minus
  style keys, plus flattened style props, plus `VariantProps<typeof xStyle>`, plus
  `className`.

`BaseBox` (`ui/box/BaseBox.tsx`) is the shared View primitive. `ThemeProvider` is now a
plain `View` applying nativewind `vars()` colour maps from its `config.ts` and calling
`colorScheme.set(mode)`. Colour tokens resolve through `tailwind.config.ts`, consumed
type-safely by `useThemeColor`.

Do not reintroduce `GluestackUIProvider`, `OverlayProvider`, `ToastProvider`, or
`tailwind-variants` as a dependency.

## Testing

- Jest with `@react-native/jest-preset`; setup in `jest.setup.js`.
- Tests live in `__tests__/` folders co-located with the code under test, at every layer.
  There is no top-level test directory.
- `collectCoverageFrom` grades all of `src/`, not only test-reachable files. The
  self-selecting denominator previously overstated branch coverage by around 12 points.
- `coverageThreshold.global` is enforced and set a few points below the measured value as
  a ratchet. Raise it when coverage rises; do not lower it to make a run pass.
- `moduleNameMapper` has a specific override for `@/data/services` that must stay ordered
  before the general `@/*` alias.
- `expo-constants` is mocked with `__esModule: true`; dropping that flag silently nulls
  `appConfig` in tests.

Run:

```bash
pnpm test
pnpm test:ci
```

## Known Gaps

These are real limitations of the current code, not oversights to be silently "fixed"
mid-task. Do not build on the assumption that they already work.

**The refresh contract is unverified.**
`src/data/services/httpClient/services/refresh-client.ts` assumes
`POST {baseURL}/refresh-token` with `{ refreshToken }` in the body and an `accessToken`
in the response. No backend has confirmed this. Before relying on auth refresh in a real
environment, confirm the contract and update the client and its doc comment together.

**Global error hooks are unwired.**
`errorHandler`'s `onError`, `onAuthError`, and `onNetworkError` config hooks have no
callers, and nothing reads `recoveryStrategy.shouldShowAlert`. There is no global toast or
alert layer. An error is only visible if a screen renders the query's `error` or the
`ErrorBoundary` catches it. The Sentry call site is a placeholder.

**No query key factory.**
Query keys are inline literal arrays. Nothing centralizes or derives them. There are also
no write mutations and therefore no `invalidateQueries` or `setQueryData` usage anywhere,
so there is no established invalidation pattern to copy. Adding the first mutation means
choosing that pattern — raise it rather than inventing one silently.

**`useResponseDetail` is a `useMutation` wrapping a GET.**
This exists to get imperative `getDetail(id)` semantics. It is not the idiom to copy for
new read paths; use `useQuery` and thread the `signal`.

**Route params are not really typed.**
`RootStackParamList` is declared as `Record<keyof typeof RouteName, NavigatorParamsType>`,
so every route shares one params type and `navigate('Main', anything)` typechecks. Per-route
param typing does not exist yet.

**No state persistence.**
Neither the Zustand store nor the query client persists across launches.
